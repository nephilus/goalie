# Development

## Prerequisites

Install Node.js 24.14 or newer, Bun 1.4.2, Podman, and the pinned `pg0` binary. The devcontainer installs the pinned pg0 v0.15.2 Linux x86_64 binary and verifies checksum `06c4678ff7b461dba8ed1f95c5e202ead3b57b70f549a22c17a94985121c0bf5`. Do not use a runtime CDN or commit generated dependencies.

The [devcontainer Dockerfile](../.devcontainer/Dockerfile) contains the pinned pg0 download and checksum-verification commands. Outside the devcontainer, install that binary on your PATH and ensure Node24 is the active `node`.

## Fresh isolated instance

Install dependencies and create a new ignored instance. The generic ports below are defaults; choose unused loopback ports when another process already uses them.

```sh
bun install --frozen-lockfile
bun run local:setup --instance-dir .local/dev --variant demo \
  --app-url http://127.0.0.1:4310 \
  --dex-issuer http://127.0.0.1:5558/dex \
  --listen-port 5558 --database-port 54329
bun run db:start -- --instance-dir .local/dev
```

`--variant demo` creates synthetic Dex identities (admin, editor, viewer); `--variant blank` creates only a synthetic administrator. Setup writes private mode-0600 credentials and refuses to overwrite an existing instance. It does not seed business records.

`db:start` stays in the foreground to supervise PostgreSQL. Keep it running in its own terminal; start Dex in another terminal, then use a third for migrations and the app. Read your synthetic login from `.local/dev/credentials.json` privately; do not paste its passwords into issues or chat.

Start Dex with the same pinned image and local-only hardening used by the project:

```sh
podman run --rm --name goalie-dev-dex --network=host \
  --userns=keep-id --user=1000:1000 --cpus=.5 --memory=256m \
  --security-opt=no-new-privileges --cap-drop=ALL \
  -v "$PWD/.local/dev/dex:/data:Z" \
  registry-1.docker.io/dexidp/dex@sha256:8499afd690c437f52301efd2b05b2455da5bd2dfc20332cd697dc9937f808462 \
  dex serve /data/config.yaml
```

Do not publish these loopback services or their credentials. The Dex callback generated by setup is exactly `http://127.0.0.1:4310/auth/callback` for the example ports.

## Migrate, seed, and run

Run the migration runner before serving the app. Seeding is optional and is strictly synthetic/nonproduction.

```sh
# `node --env-file` fills only missing variables. Use `env -i` so a different
# instance's database, TLS, provider, or authentication settings cannot leak in.
env -i PATH="$PATH" HOME="$HOME" \
  node --env-file=.local/dev/.env --import tsx scripts/migrate.ts

env -i PATH="$PATH" HOME="$HOME" \
  node --env-file=.local/dev/.env --import tsx scripts/seed-work.ts

env -i PATH="$PATH" HOME="$HOME" \
  node --env-file=.local/dev/.env node_modules/@react-router/dev/bin.cjs dev \
  --host 127.0.0.1 --port 4310
```

Open `http://127.0.0.1:4310`. The demo seed creates synthetic people, two goals, three workstreams, eight items, and four tags, and is a no-op when business records already exist. It refuses a workspace containing non-example identities. For a blank instance, omit `seed-work.ts`; the configured `AUTH_BOOTSTRAP_EMAIL` can bootstrap the first matching OIDC identity. People provisioning after bootstrap is an authorized operator/API/MCP operation; the People page edits existing profiles only.

On the first development load, Vite may still be optimizing dependencies. If the page renders but controls do not respond and the browser reports 504 responses for `/node_modules/.vite/deps/`, wait for optimization to finish and reload. This is a development-server recovery, not an instruction to ignore production errors.

## Tests and builds

Run typechecking and the full TAP suite against a disposable database. Set both database variables because database-backed suites use `WORK_TEST_DATABASE_URL`; use a database dedicated to tests.

```sh
( # Run in a subshell so cleanup happens when these commands finish.
set -eu
TEST_DB_PORT="${TEST_DB_PORT:-55432}" # Choose an unused loopback port.
TEST_DB_NAME="goalie-docs-postgres-$$"
podman run --detach --rm --name "$TEST_DB_NAME" \
  --publish "127.0.0.1:${TEST_DB_PORT}:5432" \
  --env POSTGRES_USER=goalie --env POSTGRES_PASSWORD=goalie_ci \
  --env POSTGRES_DB=goalie_ci registry-1.docker.io/library/postgres:18.1
trap 'podman rm --force "$TEST_DB_NAME" >/dev/null 2>&1 || true' EXIT
trap 'exit 130' INT
trap 'exit 143' TERM
for attempt in $(seq 1 60); do
  if podman exec "$TEST_DB_NAME" pg_isready -U goalie -d goalie_ci >/dev/null 2>&1; then break; fi
  if [ "$attempt" = 60 ]; then echo "PostgreSQL did not become ready" >&2; exit 1; fi
  sleep 1
done

TEST_DATABASE_URL="postgresql://goalie:goalie_ci@127.0.0.1:${TEST_DB_PORT}/goalie_ci"
env -i PATH="$PATH" HOME="$HOME" DATABASE_URL="$TEST_DATABASE_URL" \
  node --import tsx scripts/migrate.ts

env -i PATH="$PATH" HOME="$HOME" bun run typecheck
env -i PATH="$PATH" HOME="$HOME" NODE_ENV=test \
  DATABASE_URL="$TEST_DATABASE_URL" WORK_TEST_DATABASE_URL="$TEST_DATABASE_URL" \
  AI_ENABLED=false OPENJEV_ENABLED=false \
  node --import tsx --test --test-reporter=tap tests/*.test.ts
env -i PATH="$PATH" HOME="$HOME" bun run build
)
```

The database container is PostgreSQL 18.1 and is removed by the trap. `--env-file` only fills missing variables; `env -i` prevents inherited `DATABASE_URL`, `DB_CA_FILE`, `DB_POOL_MAX`, OIDC, AI, and OpenJev settings from changing this run. Never point tests at a live workspace.

## MCP development

The stdio launcher has no network listener and requires both the instance environment and an explicit principal:

```sh
env -i PATH="$PATH" HOME="$HOME" GOALIE_MCP_PERSON_ID=demo-editor \
  node --env-file=.local/dev/.env --import tsx scripts/mcp.ts
```

Use an existing synthetic person ID in that variable. The launcher reads the authoritative People row and rechecks roles on calls. Database access makes this a trusted local operator boundary, not delegated authentication.
